# C-MAPSS seed (mro-copilot F4)

Engine-health data seed per `docs/04-projects/mro-copilot/data-model.md` §4/§8.

## Provenance & citation

Dataset: **NASA C-MAPSS — Turbofan Engine Degradation Simulation Data Set**
(FD001 subset). Citation: A. Saxena, K. Goebel, D. Simon, and N. Eklund,
"Damage Propagation Modeling for Aircraft Engine Run-to-Failure Simulation",
*Proc. 1st Int. Conf. on Prognostics and Health Management (PHM08)*, Denver, CO, 2008.

Allowed public dataset per `docs/02-standards/data-ethics.md` §1 (public, freely
usable with citation). Fleet identifiers in the product are fictional (`NX-E…`,
data-ethics §2) — the mapping lives in the seed, never in the UI copy.

## Pinned download — how the pins work

The original `CMAPSSData.zip` is no longer directly downloadable from the NASA
portals without an interactive challenge, so `download.sh` pins the four FD001
source files **per file** from a documented public mirror of the NASA release:

- Mirror: `https://raw.githubusercontent.com/edwardzjl/CMAPSSData/master`
  (a verbatim unpacking of the NASA `CMAPSSData.zip` — same file set, incl.
  the paper PDF and readme).

Authenticity evidence recorded at pin time (2026-09-25):

1. **Cross-mirror byte equality** — the four files were also fetched from an
   independent second mirror (`subhodeepmoitra/NASA---CMAPSSData`) and compared
   byte-for-byte: identical.
2. **Structure matches the published paper/data card** (`readme.txt`):
   `train_FD001.txt` = 20,631 rows / 100 units; `test_FD001.txt` = 13,096 rows
   / 100 units; `RUL_FD001.txt` = 100 values; 26 whitespace-separated columns
   (unit, cycle, 3 operating settings, 21 sensor channels).
3. **Pinned sha256** — verified on every download and in CI (tamper ⇒ hard
   fail, DoD):

| File | sha256 |
|---|---|
| `train_FD001.txt` | `963b5e22825b34d8b21c69e1aeb4af3e647050eb672ee8834ba4b5d91d2de0f8` |
| `test_FD001.txt` | `3cda7109ce17bafb5443f2ac926cfcf88154b941b8c4cf95eb55d1ddd6f52851` |

## Committed synthetic 3-unit sample (`sample/`)

CI and offline dev never download anything (hermetic, data-ethics §1):
`sample/` holds a **hand-authored synthetic 3-unit sample** with the same
whitespace-separated column shape (26 columns), clearly labeled with `#`
comment headers (`SYNTHETIC`). It is **not NASA data** — it is generated by the
committed deterministic generator `sample/generate-sample.py` (seeded, no
network). Roles:

| Synthetic unit (fleet id) | Trajectory | Role in fixtures |
|---|---|---|
| NX-E201 (unit 201) | healthy — deep remaining life | no alert |
| NX-E202 (unit 202) | degrading — predicted RUL inside the maintenance window at cutoff | alert fixture (`leadCycles ≥ 5`, FR-18) |
| NX-E203 (unit 203) | 6 observed cycles at cutoff | insufficient-history honesty case (`latestRul: null` renders "—", D-15 precedent) |

The committed sample is regenerated byte-identically by
`python3 sample/generate-sample.py` (deterministic: fixed seed, no clock).

## Downloaded files (gitignored)

`download.sh` writes the real FD001 files into `data/` (gitignored). The seed
uses `data/` when present and falls back to the committed synthetic sample —
engine units record which source they came from (`dataset: cmapss-fd001` vs
`synthetic-sample`) and the UI labels synthetic units honestly.

```bash
./download.sh                       # fetch + verify pinned sha256 → data/
CMAPSS_VERIFY_ONLY=1 ./download.sh  # verify already-downloaded files only
```
